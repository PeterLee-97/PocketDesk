# PocketDesk — 아이폰 16 Pro를 위한 "덱스(DeX) 모드"

아이폰을 모니터·TV에 연결하면 **모니터에는 창(윈도우)이 뜨는 데스크톱**이, **아이폰 화면은 트랙패드와 키보드**가 되는 앱입니다. 삼성 DeX처럼 큰 화면에서 인터넷, 문서, 파일, 동영상을 다룰 수 있게 만들었습니다.

```
 ┌──────────────── 모니터 / TV ─────────────────┐
 │  [바탕화면 아이콘]   ┌─ 인터넷 ──────── ─ □ × ┐ │
 │                     │ ◀ ▶ ⟳  google.com     │ │
 │                     │                        │ │
 │                     └────────────────────────┘ │
 │ ⊞ │ 🌐 📁 📝 🧮 ⚙︎                  🔋 82%  오후 3:42 │
 └───────────────────────────────────────────────┘
        ▲ USB-C → HDMI (또는 AirPlay 무선)
 ┌── 아이폰 ──┐
 │ 시작 창 Esc │
 │  트랙패드   │  ← 한 손가락: 포인터, 탭: 클릭, 두 손가락: 스크롤
 │ [왼쪽][오른쪽]│
 └────────────┘
```

---

## 1. 조사 결과 — 왜 이런 방식인가요?

- **하드웨어는 충분합니다.** 아이폰 16 Pro의 **A18 Pro**는 맥북 네오(MacBook Neo)에 들어간 칩과 같고, 맥북 네오는 이 칩으로 macOS를 돌립니다. 아이폰 16 Pro의 USB-C는 DisplayPort 영상 출력(최대 4K HDR)도 지원합니다.
- **막혀 있는 건 소프트웨어입니다.** iOS 27까지도 아이폰에는 공식 데스크톱 모드(아이패드의 스테이지 매니저 같은 것)가 없습니다. 모니터를 연결하면 기본적으로 **화면 미러링**(세로 화면 + 검은 여백)만 됩니다. 아이폰에서 스테이지 매니저를 띄운 사례는 보안 취약점을 이용한 시연뿐이라 실사용용이 아닙니다.
- **앱이 할 수 있는 것:** iOS는 앱이 외부 디스플레이에 **자기만의 화면**을 그릴 수 있게 허용합니다(키노트, 동영상 앱이 쓰는 방식). PocketDesk는 이 기능으로 외부 화면 전체에 데스크톱을 직접 그립니다.
- **앱이 할 수 없는 것:** iOS 샌드박스 때문에 **다른 앱(카카오톡, 유튜브 앱 등)을 창으로 띄울 수 없습니다.** 이건 성능 문제가 아니라 **권한 문제**입니다. 아이패드의 스테이지 매니저가 되는 이유는 그게 "앱"이 아니라 **운영체제 자체**(윈도우를 합성하는 시스템 프로세스)이기 때문입니다. App Store 앱은 그 시스템의 클라이언트일 뿐이라, 자기 화면만 그릴 수 있고 다른 앱의 화면은 건드릴 수 없습니다. 맥북 네오(A18 Pro)가 증명하듯 칩 성능은 충분하지만, 성능은 애초에 걸림돌이 아니었습니다. 이 벽을 진짜로 허무는 유일한 길은 탈옥(jailbreak)인데, iOS 18.x·A18용 공개 탈옥이 없고 업데이트마다 깨지며 보안상 권장되지 않아 현실적인 선택지가 아닙니다.

### 그래서 두 가지 방법을 모두 넣었습니다
1. **내장 앱 + 웹** — 브라우저·파일·메모·뷰어를 앱 안에 직접 만들었습니다. 웹 서비스(YouTube, Gmail, Google 문서, 네이버, Notion 등)는 브라우저로 사용합니다. App Store의 "External Display Browser (XeOS)"도 같은 원리입니다.
2. **원격 데스크톱(VNC)** — "다른 앱도 쓰고 싶다"는 요구의 현실적인 돌파구입니다. 설치형 프로그램은 iOS가 아니라 **진짜 컴퓨터에서 돌리고**, 아이폰+모니터는 그 화면과 트랙패드 역할을 합니다. 내 PC·Mac·미니PC·클라우드 PC에 연결하면 **그 안의 모든 프로그램**(카카오톡 PC판, 오피스, VS Code, 포토샵 등)을 트랙패드와 키보드로 그대로 씁니다. 탈옥 없이, App Store 규정 안에서 동작합니다.

## 3. 준비물

- **아이폰 16 Pro** (iOS 18 이상). USB-C가 있는 다른 아이폰(15 Pro 등)에서도 동작합니다.
- **USB-C → HDMI 케이블/어댑터** 또는 **HDMI 포트가 있는 USB-C 허브**(충전 포트(PD) 있는 허브 권장), 또는 USB-C 입력 모니터. *Apple TV·AirPlay TV가 있으면 무선(화면 미러링)으로도 됩니다.*
- **블루투스 키보드** (권장 — 아이폰 화상 키보드로도 입력할 수 있습니다)
- 설치용: **Mac + Xcode** (없으면 4-B 참고)

## 4. 설치

### 4-A. Mac + Xcode (권장)

1. Mac App Store에서 **Xcode**를 설치합니다(최신 버전).
2. `PocketDesk` 폴더의 **`PocketDesk.xcodeproj`** 를 엽니다.
3. 왼쪽에서 파란 `PocketDesk` 프로젝트 → **TARGETS › PocketDesk › Signing & Capabilities**
   - **Team**: 내 Apple ID 선택 (없으면 *Add an Account…* 로 로그인 — 무료 Apple ID도 됩니다)
   - **Bundle Identifier**: `com.yourname.pocketdesk` 의 `yourname`을 내 영문 이름 등으로 바꿉니다(전 세계에서 겹치지 않아야 함).
4. 아이폰을 Mac에 케이블로 연결 → 아이폰 **설정 › 개인정보 보호 및 보안 › 개발자 모드** 켜기(재시동).
5. Xcode 위쪽에서 내 아이폰을 선택하고 **▶ (Run)**.
6. 처음 실행할 때 "신뢰하지 않는 개발자"가 나오면: **설정 › 일반 › VPN 및 기기 관리** → 내 Apple ID → **신뢰**.

> 무료 Apple ID로 설치한 앱은 **7일 후 만료**됩니다. 그때 Xcode에서 다시 ▶를 누르면 됩니다. (유료 Apple Developer Program은 1년)

### 4-B. Mac이 없을 때

**방법 1 — GitHub Actions로 빌드 (Apple 공식 도구 사용, 권장)**
1. 이 폴더를 GitHub 저장소에 올립니다. `main` 브랜치에 올라가면 빌드가 자동으로 시작됩니다.
2. 직접 다시 돌리려면 저장소의 **Actions** 탭 → **Build unsigned IPA** → *Run workflow*.
3. 완료되면 *Artifacts*에서 `PocketDesk-unsigned-ipa`를 내려받습니다.
4. Windows/Mac용 **Sideloadly**(또는 AltStore)로 아이폰에 설치합니다 — 내 Apple ID로 서명됩니다. 아이폰에서 개발자 모드 켜기 + 앱 신뢰 절차는 4-A의 4·6번과 같습니다.

**방법 2 — 함께 드린 `PocketDesk-unsigned-experimental.ipa` (실험적, 저장소에는 포함하지 않음)**
- Apple 도구 없이 리눅스에서 직접 컴파일·링크한 버전입니다. 실제 iOS SDK로 컴파일했고 사용하는 시스템 라이브러리·심볼도 검사했지만, **실기기에서는 테스트하지 못했습니다.** iOS 18 이상 필요. Sideloadly로 설치하세요. 실행이 안 되면 방법 1이나 4-A를 사용해 주세요.

## 5. 사용법

1. PocketDesk를 연 상태에서 모니터에 연결합니다 → 모니터에 데스크톱이 뜨고, 아이폰은 트랙패드가 됩니다.
2. 처음 연결하면 도움말 창이 열립니다.

### 트랙패드 (아이폰 화면)

| 동작 | 기능 |
|---|---|
| 한 손가락으로 움직이기 | 포인터 이동 (빠르게 움직일수록 멀리) |
| 탭 / 두 번 탭 | 클릭 / 더블클릭 |
| **두 번 탭한 채로 움직이기** 또는 **길게 누른 뒤 움직이기** | 드래그 (창 옮기기, 글자 선택) |
| 두 손가락 탭 | 오른쪽 클릭 (메뉴) |
| 두 손가락으로 쓸기 | 스크롤 (관성 있음) |
| 세 손가락 탭 | 가운데 클릭 (링크를 새 탭으로) |
| 아래 [왼쪽]/[오른쪽] 버튼 | 실제 마우스 버튼처럼 누르고 있는 동안 드래그 |

위쪽 버튼: **시작**(시작 메뉴) · **창**(열린 창 목록) · **Esc** · **키보드**(화상 키보드) · **어둡게**(아이폰 화면을 꺼서 배터리 절약, 트랙패드는 계속 동작) · **더보기**

### 키보드

- 블루투스 키보드를 연결하면 바로 입력됩니다. 아이폰 화면 오른쪽 위에 `⌨︎ 주소창`처럼 **지금 입력이 들어가는 곳**이 표시됩니다.
- 한/영 전환: **Ctrl+Space** 또는 🌐 키. (설정 › 일반 › 키보드 › 하드웨어 키보드에서 *Caps Lock으로 언어 전환*을 켜면 Caps Lock으로도 전환)
- 키보드가 없으면 입력란을 클릭할 때 아이폰 화상 키보드가 자동으로 뜹니다. 키보드 위 줄의 **Ctrl**을 누른 뒤 `c`/`v`를 누르면 복사/붙여넣기입니다.

| 단축키 (⌘ 또는 Ctrl) | 기능 |
|---|---|
| ⌘T / ⌘N / ⌘W | 새 탭 / 새 창 / 탭·창 닫기 |
| ⌘L, ⌘R, ⌘[ ⌘] | 주소창, 새로 고침, 뒤로·앞으로 |
| ⌘+ / ⌘− / ⌘0 | 확대 / 축소 / 원래 크기 |
| ⌘C ⌘X ⌘V ⌘A ⌘Z | 복사·잘라내기·붙여넣기·모두 선택·실행 취소 |
| ⌥Tab (⌘Tab) | 창 전환 |
| Ctrl+Tab | 브라우저 탭 전환 |
| ⌘Esc 또는 Ctrl+Esc | 시작 메뉴 |
| ⌘M / ⌘, | 최소화 / 설정 |

### 팁

- **충전되는 USB-C 허브**를 쓰면 오래 써도 배터리 걱정이 없습니다.
- 글자가 너무 작거나 크면: 데스크톱 **설정 › 화면 크기**.
- 붙여넣을 때마다 "붙여넣기 허용" 창이 뜨면: 아이폰 **설정 › 앱 › PocketDesk › 다른 앱에서 붙여넣기 › 허용**.
- 아이폰 **'파일' 앱 › 나의 iPhone › PocketDesk** 폴더에 넣은 파일은 데스크톱의 **내 파일**에 보입니다. 다운로드한 파일은 `다운로드` 폴더에 저장됩니다.

## 6. 한계 (솔직하게)

- **다른 아이폰 앱을 이 창 안에 띄울 수는 없습니다** (iOS 정책 — 성능이 아니라 권한의 문제). 대신: 웹 서비스는 브라우저로, 설치형 프로그램은 **원격 데스크톱**으로 사용하세요. 그 밖의 선택지는 아래 "다른 앱을 쓰는 방법들" 참고.
- **PocketDesk가 화면에 떠 있어야** 데스크톱이 유지됩니다. 홈 화면으로 나가면 모니터는 일반 미러링으로 돌아가고, 앱으로 돌아오면 창들이 그대로 복원됩니다. 아이폰을 잠그면 화면이 꺼집니다(연결 중에는 자동 잠금이 꺼집니다).
- 웹페이지는 가상 마우스 이벤트로 조작하기 때문에 **파일 업로드 버튼, 드래그 앤 드롭, CSS로만 만든 마우스오버 메뉴** 등 일부 기능은 동작하지 않을 수 있습니다. 입력란에는 깜빡이는 커서 대신 파란 테두리가 표시됩니다.
- **블루투스 마우스**는 iOS가 아이폰에서 마우스 입력을 앱에 넘겨주는 경우에만 동작합니다(기기·iOS 버전에 따라 다름). 트랙패드는 항상 동작합니다.
- 이 코드는 클라우드 환경에서 **실제 iOS SDK로 컴파일 검증**했고 웹 입력 처리 스크립트는 브라우저 엔진에서 36개 시나리오로 테스트했지만, **실제 아이폰과 모니터로는 테스트하지 못했습니다.** 동작이 이상하면 Xcode 콘솔 로그와 함께 알려 주세요.

## 6.5 다른(설치형) 앱을 쓰는 방법들

"웹만 쓰는 버전"을 넘어서려면, iOS에서 허용되는 길은 결국 "앱을 다른 곳에서 돌리고 화면만 가져오기"입니다. 성능(A18 Pro)은 충분하니 아래 중 하나를 고르면 됩니다.

| 방법 | 무엇을 쓸 수 있나 | 필요한 것 | PocketDesk 지원 |
|---|---|---|---|
| **원격 데스크톱(VNC)** ★추천 | 내 PC/Mac/미니PC의 **모든 프로그램** | 켜 둘 컴퓨터 1대 + 같은 Wi-Fi(또는 포트 개방) | **내장** (원격 데스크톱 앱) |
| 클라우드 PC | Windows 전체 (Windows 365, Shadow, Parsec 등) | 월 구독 | 그 서비스에 VNC 서버를 깔면 내장 앱으로, 아니면 각 전용 앱 |
| 에뮬레이션 (UTM SE) | 로컬에서 돌리는 **리눅스 데스크톱 앱** | 없음(아이폰만) — 단 JIT가 없어 느림 | 별도 앱(App Store/AltStore). PocketDesk 밖에서 실행 |

- **원격 데스크톱**이 가장 현실적입니다. 집에 늘 켜 두는 PC나 중고 미니PC(약 15~25만 원)가 있으면, 카카오톡 PC판·한글·오피스·개발도구 등 그 PC의 모든 것을 모니터에서 그대로 씁니다. 설정은 README 5번 "사용법"의 원격 데스크톱 항목과 앱 안의 안내를 따르세요.
- **UTM SE**는 아이폰 안에서 리눅스를 직접 돌리지만, iOS가 일반 앱의 JIT를 막아 번역(TCG) 방식이라 느립니다. 가벼운 작업용입니다.
- 왜 이게 최선인가: 다른 앱의 창을 PocketDesk 안에 직접 합성하는 건 운영체제만 할 수 있는 일이라, 탈옥 없이는 어떤 앱도 불가능합니다. "앱을 제대로 돌리는 환경(진짜 OS)에서 돌리고, 아이폰은 화면·트랙패드가 된다" — 이게 iOS에서 데스크톱 경험을 가장 멀리 밀어붙이는 방법입니다.

### iOS 27 관련

iOS 27 SDK로 빌드한 앱은 외부 디스플레이 화면을 자동으로 받지 못하고, 뷰 컨트롤러에서 "scene accessory"를 등록해야 합니다. PocketDesk는 이를 처리하고 있습니다(`App/SceneDelegates.swift`의 `ExternalDisplayAccessory`). Xcode 26/27 모두에서 빌드됩니다.

## 7. 문제 해결

| 증상 | 해결 |
|---|---|
| 모니터에 아이폰 화면(미러링)만 보여요 | PocketDesk를 앞에 띄운 상태인지 확인 → 케이블을 뺐다 다시 연결. AirPlay는 앱을 연 뒤 화면 미러링을 시작하세요. |
| Xcode: *Failed to register bundle identifier* | Bundle Identifier를 다른 고유한 이름으로 바꾸세요. |
| 아이폰에서 앱이 안 열려요 (신뢰하지 않는 개발자) | 설정 › 일반 › VPN 및 기기 관리 › 신뢰 |
| 입력이 안 들어가요 | 입력란을 한 번 클릭 → 아이폰 위쪽의 `⌨︎ …` 표시 확인. 블루투스 키보드는 설정 › Bluetooth에서 연결 상태 확인. |
| 포인터가 너무 느려요/빨라요 | 데스크톱 설정 › 트랙패드 · 마우스 속도 |

## 8. 개발자용: 구조

```
PocketDesk/
├─ App/          AppDelegate, 아이폰·외부 디스플레이 Scene, iOS 27 scene accessory 등록
├─ Core/         가상 입력 모델(PointerEvent, KeyInputTarget), 세션, 설정, 테마, 파일 저장소
├─ Desktop/      데스크톱 루트(포인터·키보드 라우팅, 창 관리자), 창, 작업 표시줄, 시작 메뉴,
│                아이콘, 메뉴·대화상자·토스트, 커서, 공통 컨트롤(버튼·입력란·슬라이더·목록)
├─ Apps/         인터넷(WKWebView + 주입 스크립트), 내 파일, 메모, 텍스트 편집기, 뷰어, 계산기, 설정, 도움말
│   └─ RemoteDesktop/  VNC(RFB 3.8) 클라이언트 — Network.framework 소켓, DES 인증, Raw·CopyRect·Hextile 디코더, 입력 매핑
└─ Phone/        아이폰 화면: 트랙패드, 키보드 입력 수집기, 블루투스 키보드/마우스(GameController)
```

- 외부 디스플레이는 **터치·키보드 입력을 받지 않는 화면**이라, 모든 클릭·스크롤·키 입력을 앱이 직접 만들어 전달합니다(`Core/Input.swift`, `DesktopViewController`의 hit-test 라우팅).
- 웹페이지 조작은 격리된 JavaScript 월드에 주입한 브리지(`Apps/Browser/BrowserScripts.swift`)가 DOM 이벤트·포커스·선택·편집 명령으로 바꿉니다. 다른 출처의 iframe에도 비밀 토큰으로 보호된 메시지로 전달합니다.
- 키보드는 아이폰의 보이지 않는 텍스트 뷰가 받아 **차이(diff)만 전달**하므로 한글 조합(ㅎ→하→한)도 그대로 동작합니다(`Phone/KeyboardSinkView.swift`).
- 원격 데스크톱은 같은 입력 시스템(PointerTarget/KeyInputTarget)을 그대로 재사용해 VNC 이벤트로 변환합니다. 포인터·키보드·스크롤이 데스크톱 창과 똑같이 동작합니다.
- 최소 지원: iOS 16 (Xcode 빌드), Swift 5 언어 모드.

### 검증 (이 환경에서)
- 전체 앱(31개 파일)을 실제 iOS 18.6 SDK로 컴파일 — 오류·경고 0개. 링크한 바이너리가 참조하는 시스템 라이브러리·심볼도 iOS 18.6에 존재하는지 검사.
- 웹 입력 브리지: 브라우저 엔진에서 36개 시나리오 통과.
- VNC 디코더: 실제 Swift 디코드 코드(Raw·CopyRect·Hextile)를 리눅스 네이티브로 빌드해 독립 인코더와 왕복 테스트 — 264,000바이트 전부 일치(0 불일치).
- VNC 인증: 비트 반전 로직을 독립 구현과 대조(5개 비밀번호 전부 일치), 응답이 표준 DES-ECB임을 확인.
- **실제 아이폰·모니터·실제 VNC 서버로는 테스트하지 못했습니다.**
